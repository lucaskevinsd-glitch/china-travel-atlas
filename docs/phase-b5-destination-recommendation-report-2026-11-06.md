## 1. 推荐系统架构

新增独立模块 `assets/js/services/recommendations.js`（纯函数，无 DOM、无网络），详情页调用，旧的单层"相关目的地"（`CTA.pages._relatedFor`）保留原样（仍被 `tests/unit/related.test.mjs` 覆盖，不再作为 UI 主入口）。

```
详情页 (#/dest/<id>)
  └─ CTA.recommendations.getRecommendations(index, currentId, CTA.plannerGeo, {themes, types})
       ├─ M1 附近：planner-geo.haversineKm（复用，不自建距离计算）
       ├─ M2 相似体验：themes / type（频次加权）
       └─ M3 延伸探索：province / city / themes / 500km 内加分
  └─ 三层依次去重（M1 → M2 → M3），每层至多 4 张，空层隐藏
```

- 计算在本地完成：每次详情页渲染时对 42 条索引条目做一次 O(42) 计算，无需静态推荐索引，无新增依赖，图片复用现有 `coverThumb` 与 SW 缓存。
- 结果稳定复现：排序键为（分数/距离，索引原顺序），无随机因素；同一输入两次调用输出完全相同（单测覆盖）。
- 性能：42 条全量计算单次 < 1ms（Node 实测），无感知开销；不缓存结果（数据量极小，缓存无收益且增加失效风险）。

## 2. 三个推荐层次的实现情况

| 层次 | 信号 | 阈值/上限 | 空层处理 |
|---|---|---|---|
| M1 附近值得一起游览 | WGS-84 景区坐标直线距离（复用 B4 `haversineKm`） | ≤300km，按距离升序，至多 4 张 | 无邻居时整层隐藏 |
| M2 相似旅行体验 | 共同主题（频次加权）+ 同类型 | ≥4 分，至多 4 张，同一类型至多 3 张 | 无匹配时整层隐藏 |
| M3 延伸探索 | 同省/同市 + 共同主题（频次加权）+ 500km 内加分 | ≥3 分，至多 4 张 | 无匹配时整层隐藏 |

- M1 只用实际地理距离判断相近，不只看行政省份（同省可远如喀什→喀纳斯 1358km，跨省可近如宏村→黄山 22km——与 B4 同一原则）。
- M1 距离只描述为"直线距离约 X 公里"，不冒充道路距离与交通时间。
- M2 推荐理由具体：点明共同主题标签与同类型（如"共同主题：山岳、自然风光；同为山地类型"），不写"风景优美"类空话；不只因名称相似推荐。
- M3 不宣称具体交通路线；理由只陈述事实（"同在浙江省""同属「古镇古城」主题""直线距离约 X 公里"）。
- 当前目的地不推荐自己；三层之间不重复（M1 优先，M2 排除 M1，M3 排除 M1+M2）。
- 缺失坐标者可参与 M2/M3，但不伪造距离（M1 为空，M3 无距离加分）；缺失主题者不虚构匹配（M2 仅靠同类型 < 阈值时为空）。

## 3. 推荐评分与排序逻辑

权重全部集中在 `recommendations.js` 的 `REC` 对象中。

### 主题频次加权（M2/M3 共用，动态计算）

通用主题（家庭 22 条、摄影 26 条、历史人文 21 条）几乎不能区分体验，稀有主题（山岳 7 条、徒步 6 条、古镇 8 条、海岛海岸 3 条、草原沙漠 2 条）才是体验的指纹。因此共同主题按其在全部 42 条中的出现频次加权（由模块在运行时动态计算，随目的地扩充自动更新）：

- 出现 ≤8 条的主题：3 分
- 出现 ≤20 条的主题：2 分
- 出现 >20 条的主题：1 分

本轮实测：mountains/hiking/ancient-town/coastal/grassland-desert = 3 分；nature = 2 分；historic/family/photography = 1 分。

该设计的直接效果：乌镇的 M2 正确排除洪崖洞（仅共享摄影/家庭两个通用主题，得 2 分 < 阈值 4），而西江千户苗寨、婺源篁岭、宏村（共享稀有主题"古镇古城"）居前。

### 各层计分

- **M1**：无分数，按直线距离升序。300km 上限与 B4 相邻日 info 级一致（300km 内属可顺路转移）。
- **M2**：Σ（共同主题频次权重）+ 同类型 3 分；阈值 4 分。含义：2 个通用主题（2 分）不足；1 个稀有主题 + 同类型（6 分）足；仅同类型（3 分）不足。同一类型至多 3 张，避免一组推荐全是同一种景观。
- **M3**：同省 3 分 + 同市 2 分（与同省叠加）+ Σ（共同主题频次权重）+ 500km 内 1 分；阈值 3 分。含义：同省 alone 即达标（地区延伸）；同市 alone 达标；1 个稀有主题 alone 达标（主题延伸）；2 个通用主题 alone 不足（那是 M2 的事）。

### 排序与去重

- M1 按距离升序；M2/M3 按分数降序；分数/距离相同时按索引原顺序（稳定、可复现）。
- 去重顺序 M1 → M2 → M3；当前目的地全程排除。

## 9. 遗留问题

1. **M1 对 13/42 个目的地为空**：偏远目的地（亚龙湾、布达拉宫、喀什等）300km 内无邻居，M1 整层隐藏。这是数据现状（42 条覆盖 31 省，密度不足），非算法问题；随 B6 目的地扩充至 60+ 条，M1 覆盖会自然提升。
2. **M3 对 8/42 个目的地为空**：同上，地区/主题延伸在稀疏省份上匹配不足；同样随数据扩充改善。
3. **无交通时间数据**：M1 只给直线距离，不判断交通可达性；300km 内是否"值得一起游览"仍需用户结合实际交通判断（与 B4 同一遗留）。
4. **K80 真机、读屏、旧客户端 SW 线上升级（20261105e→f）未观测**（与 B1–B4.1 相同遗留）。
5. 旧的 `_relatedFor` 单层计分函数保留在 `pages-detail.js`（仍被单测覆盖），UI 已不再使用；是否删除由总设计师定夺。
