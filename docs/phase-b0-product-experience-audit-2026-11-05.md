### 2.4 首页机制问题（与图片无关，但同等致命）

## 五、发现页面全新信息架构（灵感中心）

### 5.1 设计原则

- 跳出"数据库浏览器"思路，以**灵感激发→兴趣→转化（进入详情/规划/收藏）**为动线。
- 静态架构不变：所有"动态感"内容用确定性算法从静态数据派生（日期种子轮换），新闻用带过期时间的静态 JSON。
- **不删除现有功能**：筛选器保留，移至灵感模块之后作为"全部目的地"部分的工具条。

### 5.2 推荐结构（自上而下）

```
#/discover · 旅行灵感中心
├── 1. 今日灵感（Hero）
│    每日一目的地：日期种子从 42 条确定性轮换，大图+一句话推荐语+进入详情 CTA
│    附"换一个"按钮（种子+1，纯前端）
├── 2. 快捷筛选条（现有 keyword/province/theme/season，紧凑单行）
├── 3. 季节旅行（4 卡：春/夏/秋/冬）
│    按月份自动高亮当前季节；每卡链向预置筛选（如秋→season=autumn）
│    文案示例：秋"红叶、胡杨、梯田金黄的季节"
├── 4. 主题旅行（横滑卡组，8–10 个主题）
│    中国最美公路 / 古镇漫游 / 海岸线旅行 / 雪山与湖泊 / 徒步路线 /
│    摄影圣地 / 亲子自然 / 博物馆之旅 / 非遗体验
│    每个主题 = curated ID 列表（config.js 静态配置）→ 主题落地视图（复用卡片网格）
├── 5. 小众目的地（编辑精选 6–8 张）
│    config.js `hiddenGems: [ids]` 静态配置；标注"人少景美"角标
├── 6. 趣味探索（问答式卡片，点选跳预置结果）
│    "只有三天去哪最值得？"→ 规划页预设3天
│    "一个人旅行去哪？"→ 安全/交通便利筛选视图
│    "中国鲜为人知的绝美湖泊"→ 湖泊主题视图
│    "第一次去西部"→ 西部省份组合视图
│    全部为静态 editorial 链接，无后端问答
├── 7. 旅行新鲜事（新闻流）
│    数据：data/news.json，每条 {title, date, source, sourceUrl, expiresAt, province?}
│    渲染时过滤过期条目；过期自动隐藏（无需人工下线）
│    来源优先级：文旅部/省级文旅/景区官方；每条保留发布时间+来源+原文链接
│    上限显示 8 条，"查看全部"进归档视图（含已过期归档）
└── 8. 全部目的地（现有卡片网格+筛选结果，保留"更多推荐"）
```

### 5.3 持续更新能力设计

| 模块 | 更新方式 | 成本 |
|---|---|---|
| 今日灵感 | 全自动（日期种子） | 零 |
| 季节旅行 | 全自动（月份判断） | 零 |
| 主题/小众/趣味 | 改 config.js 数组 | 极低 |
| 旅行新鲜事 | 追加 news.json 条目 | 低（人工采集，单条约 2 分钟） |

### 5.4 信息可靠性保障

- 不得编造新闻：news.json 每条必须有真实 sourceUrl；渲染时标题即原文标题，不改写。
- 不得将过期活动伪装成当前：expiresAt 为必填字段，过期条目永不出现在"新鲜事"流。
- 目的地转化：每个灵感模块的卡片均链向 `#/dest/<id>` 详情页。

## 七、目前最影响用户体验的五个问题

1. **首页轮播零文字层（P0-1）**——首屏无信息、无行动号召，流量进来即流失。
2. **轮播图片质量（P0-2）**——洪崖洞/张掖丹霞两张弱项直接拉低"中国旅行"第一印象。
3. **主题卡图文错配（P1-1）**——"城市漫游"配宏村乡村图，编辑可信度受损。
4. **规划页无视地理距离（P1-2）**——行程草案出现拉萨→成都隔日跳，工具不可信。
5. **发现页无名横幅（P2-1）**——筛选与结果之间的一张无名大图，干扰浏览动线。
