# UI 设计学习成果严格审计 + 第二轮视觉升级方案（2026-10-28）

范围声明：本轮只审计与制定方案，**不修改产品代码、不推送、不部署**。证据分三类：① 上一轮报告原文（`docs/ui-ux-upgrade-report.md`）；② 当前仓库代码实测（`assets/css/main.css`、`assets/js/*.js`，grep + 对比度复算）；③ 今日（2026-10-28）线上真实浏览器复查：线上站四页视觉评审 + 八个参考站首页逐一重访。凡未亲见的内容，一律标注未验证，不以报告转述代替证据。

状态定义：**已验证** = 有页面或代码证据；**部分完成** = 原则采纳但落地不完整，或证据只覆盖一部分；**未完成** = 无证据，或报告措辞超出证据。

## 一、八个参考网站逐一审计

### 1. Scrolltide — 部分完成

- 实际访问：上一轮文本读取首页（文案与“55 shaders”）；今日真实浏览器重访首页正常加载，确认：深色首屏、橙蓝光晕、大号白标题、库规模 131 模板 / 66 组件 / 55 着色器 / 20 区块 / 14 界面、“13,500+ builders”。**“55 shaders”属实，今日仍在。**
- 可验证材料：首页文案、库规模数字、分类（Components / Sections / Shaders / Landing Page / Hero Section / 3D Website 等）。
- 提炼原则：叙事式滚动结构（首屏大图→主题→卡片→季节/省份入口）；全站轻动效；大标题压照片暗角 + 搜索入口。
- 已应用：首页区块顺序（`pages-home.js`：hero → 主题横滑 → 精选卡片 → 季节推荐 → 省份入口）与代码一致；hero 暗角 + 搜索入口真实存在（`main.css .hero`）。
- 未验证：滚动驱动的动态实感。两轮均未亲见其滚动动画（上一轮为文本读取，本轮为首页截图级观察），“滚动叙事”的动效部分不能算研究过；模板内页、组件详情页均未打开。
- 未实现：无。拒绝项（Shader/WebGL 背景、滚动劫持）至今未引入，正确。

### 2. Mobbin — 部分完成（流程部分未完成）

### 3. Fontshare — 部分完成（决策正确，语言核查不完整）

### 4. Coolors — 部分完成（校验已验证，取色未执行）

## 二、当前线上站的视觉问题（今日真实浏览器评审 + 代码复核）

评审覆盖首页、发现页、黄山详情页、规划页（桌面端；约 390px 手机端因浏览器工具无法设置视口宽度**未能实测**，下文移动端判断以代码 + 桌面端推断标注，不冒充实测）。

### 1. 首页首屏：照片强、文字弱、气势被容器削弱

- 视觉重心落在黄山主图中央的奇松岩石上，其次才是标题——照片赢了，但标题没有赢回注意力。眉题白色压在浅蓝天空上：hero 渐变只在图片下部（0%→55%→78%），眉题位于无暗角的顶部区域，对比不足，第一眼几乎读不到（代码证实渐变结构，评审证实观感）。
- 主视觉为内嵌圆角图（`--radius-lg 20px`、内容列 `--maxw 1080px`），宽屏下两侧留白大，杂志式大图的冲击感被削弱；搜索框 + 橙色按钮是全站最醒目的交互点，但橙色在后续页面消失，配色不统一。
- 标题层级只靠字号硬撑（28→44px、字重 800），中文标题无展示字体可用（系统字体限制，决策正确），因此标题缺乏杂志标题的性格。

### 2. 图片：资产最强，呈现最保守

- 卡片图固定 8/5 裁切（`aspect-ratio:8/5; object-fit:cover`），桌面端详情画廊限高 520px：1080px 宽下 8/5 应为 675px 高，被压到 520px 意味着上下裁切更重（除龙门图 3 有 focus 外，其余图无焦点位控制，裁切结果听天由命）。
- 卡片阴影极淡（`--shadow-sm`），近乎扁平；图片圆角顶部 14px、底部直角过渡到白底，处理平淡。
- 懒加载无占位：图片加载前是米色空白块（`background:#E7E2D4`），无骨架、无图标、无提示，今日评审亲见故宫、洪崖洞卡片出现整块空白——这是骨架屏缺失的直接后果。

### 3. 页面一致性：同一套语言，但断层在“有没有照片”

- 四页共享同一 Token（暖纸底、白卡片、深绿、14/20px 圆角、三档阴影），语言统一是真优点；但发现页、规划页完全无头图、无照片，品牌感在首页之后断崖式消失——发现页开场就是筛选卡片，规划页开场就是表单。
- 风格细节不一致：首页主题/季节/省份用圆润 pill，发现页筛选控件却是原生下拉样式；强调陶土色只在首页搜索按钮出现一次（`--accent-soft` 定义了却全站无使用），内页主操作一律深绿。

### 4. 字体、色彩、留白、圆角、阴影：体系存在，但用得单一

- 体系本身完整：字号 5 档、圆角 3 档、阴影 3 档、动效 2 档、对比度全部达标。但实际使用单一：卡片清一色白底 + 14px + 最淡阴影；阴影 md/lg 几乎只用于悬停；圆角 lg 只用于 hero/画廊。体系没有被用来制造层级差异。
- 字体：中文系统栈是正确决策（无 CJK 网络字体可用），但结果是标题与正文只有字号字重之差，没有字体性格对比；拉丁展示词只用在眉题一处，品牌识别度贡献极小。

### 5. 目的地卡片：信息完整，视觉吸引力不足

- 六张卡片完全同质：照片 + 名称 + 地区 + 简介（三行截断，常在句中断掉，如“1961年列为全国重点文物保护…”）+ 天数/季节行 + 主题标签 + 全宽描边“☆ 收藏”按钮，层层堆叠导致卡片偏高；收藏按钮每卡一个、视觉重量大，重复六次后成为噪音。
- 主题胶囊无选中态层次；“季节推荐”与“按省份浏览”两组 pill 视觉完全相同，省份行在桌面端已出现横向滚动条（`chip-scroll` 横向滚动设计），31 个省横滑查找效率低、移动端风险高。

### 6. 详情画廊：照片价值发挥不足

- 页面内只见一张大图，下方仅“1 / 3”小药丸 + “放大”按钮；slide 占 100% 宽、无箭头、无下一张 peek，用户除非点放大，否则不易发现共 3 张图。灯箱本身较好（黑底全屏、左右箭头、来源与计数），但箭头偏小且贴近屏幕边缘、底部来源文字过长。
- 多图是本站区别于普通列表的核心资产（93 张实景照片），当前呈现却把它藏在了计数药丸后面。

### 7. 交互反馈：筛选条是亮点，其余反馈弱

- 亮点：发现页筛选反馈具体可逆（选安徽省 → 结果变 1 条、出现“安徽省 ✕”与“清除全部”，URL 同步），这是 Mobbin 流程原则落得最实的一处。
- 弱点：收藏只有颜色切换 + Toast，无回弹；卡片悬停只在指针设备生效；行程编辑按钮组（上移/下移/后插/删除）每卡重复，视觉嘈杂；筛选后只剩一张卡片时孤悬左上角，右侧大片空地、无“看看其他省份”承接；规划页打开时已有一份浏览器本地旧草案、无来源说明（草案属浏览器本地存储，不是线上数据错误，但首访用户会困惑；另注意：表单默认出发日与旧草案标题日期不一致，属本地旧数据残留，不应误读为线上 bug）。

### 8. 手机端与桌面端差异（未实测，代码 + 桌面推断）

- 代码层面：≤720px 时顶部导航隐藏、底部导航出现、卡片单列、hero 降至 300px、画廊全宽——结构合理；但以下风险未经真机验证：省份横滑行在窄屏的可用性、筛选表单堆叠后的长度、画廊拇指操作区、Toast 与底部导航的遮挡关系（Toast 位于 `tabbar-h + 16px`，理论上避开了，但未实测）。
- **手机端 390px 验收必须用 Playwright Firefox 移动视口（往轮已验证可行）或 K80 真机补测，不得用本次浏览器工具的桌面截图代替。**

### 9. 动画：克制到近乎静态

- 现有动效只有卡片悬停（指针设备）、Toast、芯片 hover、画廊滚动计数；无页面切换、无滚动揭示、无视差、无加载动效。性能与减动效处理是优点，但“克制”被执行成了“几乎没有反馈动效”——收藏、筛选、图片加载三处最需要反馈的地方恰恰最弱。动画不是太多，而是太少且不在关键处。

### 10. 识别度：干净，但模板化

- 除橙色搜索按钮外无第二记忆点：无 Logo 图形、无品牌纹样、无中国旅行特有的视觉符号（印章、坐标、山水线条、地名书法感排版均无）、无编辑性设计手法（期号、栏目线、跨页大图、图片说明体例）。整体像“做得干净的通用内容模板”，不像一本“中国旅行图鉴”。这是第一轮未达预期的总根源：**第一轮修的是信息架构与正确性（筛选可见、事实完整、对比度达标），改的是“信息怎么摆”；几乎没改“视觉怎么让人记住”。**

## 三、第二轮升级方案

总方向：**从“信息摆得对”升级到“视觉记得住”**。照片仍是主角；所有改动继续在零构建、零新增依赖、零网络字体、PWA 离线架构内完成；不引入 3D、WebGL、Lottie 运行时、视频背景、滚动劫持。每一项都先有前后截图对比，再谈代码。

### 1. 首页整体构图方案

- 目标：首屏一眼记住“这是一本中国旅行图鉴”，而不是“一个干净的列表站”。
- 参考依据：Scrolltide 的叙事结构（已验证）+ 今日评审指出的容器偏窄、眉题对比不足。
- 方案：① 主视觉改为近通栏（内容列 1080px 约束内图片顶格，或 hero 突破容器至视口宽，圆角只保留底部，桌面端高度 420–520px）；② 眉题可读性修复（二选一，见对比项：A. 顶部加全幅细腻暗角/眉题加半透明深色药丸底；B. 眉题移至图片下方白底区，配陶土色小标点）；③ 增加图片说明体例：图注从一行小字升级为“地名 + 省份 + 摄影来源”的编辑体例，位置固定；④ 增加一个品牌识别装置（二选一：地名印章式小标，或“第 N 期 · 覆盖 M 省”的期号式眉题，二者只选其一，不得堆叠）。
- 涉及组件：`pages-home.js` hero 区块、`main.css .hero/.hero-overlay/.hero-eyebrow/.hero-caption`、首页区块节奏（主题横滑、季节、省份入口顺序不变）。
- 预期效果：首屏视觉重心从“照片本身”变为“照片 + 标题 + 品牌”三者有序；眉题在任何天空背景下可读。
- 验收：390/768/1440 三档前后截图；眉题在浅色天空图上的对比度 ≥4.5（实测取色计算）；标题、搜索、图注三者层级在截图中可辨；无横向溢出。

### 2. 字体与色彩系统

- 目标：让现有 Token 从“存在”变为“被使用”，并给品牌一个第二记忆点。
- 参考依据：Coolors 对比度先行（已验证）、Fontshare 字重层级（已验证）。
- 方案：① 强调色体系化（二选一，见对比项：A. 陶土色升级为全站强调：区块小标点、详情页内导航激活态、规划主按钮、筛选激活态统一用陶土，搜索按钮不再孤立；B. 废除陶土强调，全站只用深绿 + 墨色，搜索按钮改深绿——二者只选其一）；② 阴影档位拉开差距：卡片默认 shadow-sm 不变，悬停 md，详情画廊/重要卡片用 md，禁止全站一档阴影；③ 字体：中文系统栈不变；拉丁展示词扩大使用范围至数字、坐标、地名拼音小字（仍限小字距大写短词），不得用于中文；④ 删除未使用的 `--accent-soft` 或给它真实用途（警告底已用同值，需合并清理，不得留死 Token）。
- 涉及组件：`main.css :root`、`.hero-search button`、`.detail-nav`、`.filter-chip`、规划主按钮、区块标题行。
- 预期效果：内页不再“橙色消失”；卡片与重要区块的层级在截图中可区分；无死 Token。
- 验收：全站强调色出现位置清单（≥4 处且一致）；全部文字组合对比度复算 ≥4.5（沿用上一轮复算方法）；Token 清理后无未引用变量。

### 3. 图片展示规范

- 目标：让 93 张实景照片的价值在列表与详情都被看见，且加载过程不出现空白块。
- 参考依据：今日评审（画廊隐藏、加载空白）+ 上一轮图片策略（懒加载、两档 srcset、破图占位，保留）。
- 方案：① 详情画廊增加可见的多图提示：缩略图条（3–5 张小图，当前张高亮）或下一张 peek（二选一，见对比项；缩略图优先，因与现有横滑 + 计数兼容）；② 画廊箭头改为桌面端可见的左右按钮（移动端仍靠横滑），灯箱箭头加大并内收、不贴边；③ 全站图片加载占位：米色底 + 居中图片符号（纯 CSS/SVG，不得引入图标库），懒加载图片进入视口前不再是空白块；④ 裁切规范：卡片统一 8/5（已是现状，保留并写进规范）；详情画廊桌面端限高 520px 的裁切问题：为每张图补 focus 字段评审（目前仅龙门图 3 有 focus），或画廊改为按 8/5 全高展示（不再压高）——二选一，见对比项；⑤ 发现页、规划页补照片：规划日卡片用目的地封面缩略图（`coverThumb` 已有数据，零新增请求）；发现页顶部加一张主题/季节相关的窄幅头图条（用已有封面图，不得新增图片文件）。
- 涉及组件：`pages-detail.js` 画廊与灯箱、`main.css .gallery/.slide-img/.lightbox`、`ui.js destCard`、`pages-planner.js` 日卡片、`pages-discover.js` 顶部。
- 预期效果：用户不点放大也能知道有 3 张图；加载过程有明确占位；规划页从纯表单变为图文行程。
- 验收：画廊 3 张图在页面内（非灯箱）均可被发现（截图 + 操作路径）；懒加载占位截图；规划日卡片含图截图；裁切后主体（人物/建筑）不被切掉（抽查 5 张）。

### 4. 卡片与信息层级规范

- 目标：卡片从“信息堆叠”变为“可扫读的比较单元”，且六张不再完全同质。
- 参考依据：Mobbin 卡片密度原则（已验证）+ 今日评审（卡片偏高、收藏按钮噪音、简介截断仓促）。
- 方案：① 收藏按钮降级：从全宽描边大按钮改为卡片右上角图标按钮（☆/★ + 文字“收藏”小字，触摸目标仍 ≥44px），卡片高度随之下降；② 信息层级重排：名称（加粗）→ 地区 + 天数/季节同一行（地区在前，比较信息在后，颜色区分）→ 简介（2 行截断，截断处不得在句中硬切，改为“简介 + 查看详情”语义，技术上仍用 line-clamp，但文案侧控制简介长度）；③ 主题标签上限：卡片上最多 3 个标签，超出收进“+N”（数据不变，只控制展示）；④ 首页精选卡片与发现页卡片允许轻微差异：首页卡片可配一句编辑推荐语（取自已有 summary 首句，不得新写文案），发现页卡片保持比较信息优先——差异只体现在信息密度，不做两套视觉风格。
- 涉及组件：`ui.js destCard`、`main.css .dest-card/.card-body/.card-meta/.fav-btn`。
- 预期效果：卡片高度下降、扫读路径为“图 → 名 → 地区/天数 → 标签”，收藏操作不再喧宾夺主。
- 验收：390/768/1440 卡片截图；卡片高度对比（改前改后）；触摸目标实测 ≥44px；标签溢出处理截图。

### 5. 页面之间的视觉统一方案

- 目标：消除“首页有照片、内页无照片”的断层，但不给工具页硬加装饰。
- 参考依据：今日评审（发现/规划页品牌断层）+ Scrolltide 叙事节奏。
- 方案：① 发现页：顶部加窄幅头图条（见第 3 条）+ 筛选卡片保留（它是本页最有条理的部分，不动结构）；筛选结果为空或只剩 1 条时，增加承接区（“看看其他省份/主题”链接组，用已有数据生成，不得编造推荐理由）；② 规划页：表单网格重排（第一行 3 字段、第二行 3 字段 + 按钮独立行，消除 6+1 不对称）；日卡片图文化（见第 3 条）+ 草案来源说明（“本草案保存在当前浏览器中”一行小字，消除首访困惑；旧草案日期与表单默认日期不一致时以草案标题日期为准并注明）；③ 详情页：删除标题下地区行与事实条第一格的重复（只保留事实条）；正文各区块加轻分隔（细线或小标题配陶土/深绿标点，二选一，与第 2 条强调色方案一致）；天气提示条改用系统配色（深绿底浅字或中性灰底，不得再用粉红报错观感）；页内导航在详情页顶部区域即可见（移至事实条之后、首屏内，或吸顶复现，二选一，见对比项）。
- 涉及组件：`pages-discover.js`、`pages-planner.js`、`pages-detail.js`、`main.css` 对应区块。
- 预期效果：四页一眼同属一站；工具页不再像裸表单；详情页信息节奏从“纯文本长流”变为“图片 → 事实 → 分组信息”。
- 验收：四页同屏风格对照截图；重复信息消除核查；天气条配色截图；页内导航首屏可见性截图。

### 6. 动画和微交互使用原则

- 目标：动画只出现在“用户需要确认结果”的地方，且全部可感知、可关闭。
- 参考依据：LottieFiles 动效预算概念（已验证其预算部分）+ 今日评审（反馈弱在关键处）。
- 原则（写入规范，不得逾越）：① 预算不变：150–250ms、仅 transform/opacity、`prefers-reduced-motion` 下全关；② 只允许三类动效：操作反馈（收藏、筛选、保存——补收藏按钮的按压/状态过渡，替代不存在的“回弹”说法）、加载占位（图片占位微光，纯 CSS）、页面内揭示（区块标题进入视口时的轻微上浮，仅用于首页区块标题与详情分组标题，用 IntersectionObserver 实现——这是上一轮声称但未做的揭示，本轮正式立项）；③ 禁止：页面切换动画、循环装饰动画、滚动劫持、视差（仍不做）、任何 JS 动画库。
- 涉及组件：`main.css` 动效 Token 与新增类、`ui.js` 收藏切换、`pages-home.js`/`pages-detail.js` 区块标题（新增 IntersectionObserver 需单测覆盖减动效分支）。
- 预期效果：收藏、筛选、保存、加载四处反馈完整；页面仍保持静态站的轻盈感。
- 验收：四处反馈的操作录屏/截图序列；减动效下全部关闭的验证；零新增 JS 依赖、零新增网络请求。

### 7. 手机端专项优化方案

- 目标：窄屏不是桌面版的压缩，而是独立可用的版本。
- 参考依据：代码中断点（720px）+ 今日评审指出的桌面端横向滚动条风险 + 上一轮移动模拟经验。
- 方案：① 省份入口：31 省横滑改为换行展示 + “展开/收起”（默认展示常用省份行，展开后全部），消除横向滚动条；② Hero：300px 高度下标题、搜索、图注不得溢出，搜索框在窄屏改为上下结构（输入框在上、按钮全宽在下）或保持一行但按钮不压缩输入框（实测决定，二选一）；③ 画廊：缩略图条在窄屏改为横滑小图；灯箱箭头在窄屏加大触摸区；④ 筛选表单：窄屏下字段单列、筛选按钮全宽、状态条芯片可换行（已可换行，保留）；⑤ 底部导航与 Toast/灯箱的遮挡关系实测：Toast 不得被底部导航遮挡，灯箱关闭按钮不得贴边；⑥ 规划日卡片：窄屏下照片缩略图在左、文字在右，编辑按钮组收进一行横滑或两行网格，不得溢出。
- 涉及组件：`main.css` 720px 断点区、`pages-home.js` 省份入口、`pages-detail.js` 画廊/灯箱、`pages-discover.js` 筛选表单、`pages-planner.js` 日卡片。
- 预期效果：390px 下无横向溢出、无横向滚动条（画廊与主题横滑等有意横滑的组件除外）、触摸目标 ≥44px。
- 验收：**390/360 视口真实截图（Playwright Firefox 移动视口 + K80 真机抽查，二者至少其一，不得用桌面截图代替）**；溢出矩阵（首页/发现/详情/规划/收藏五页 × 360/390）；触摸目标抽查。

## 四、第二轮最值得优先修改的五个问题

按“用户可见度 × 改动成本低 × 证据确凿”排序：

1. **详情画廊多图不可见**（第 3 条①②）：多图是本站最强资产，却被藏在“1/3”药丸后；改动小（缩略图条/箭头 + 灯箱箭头），效果立即可见。直接修改。
2. **首页眉题对比不足 + 主视觉气势弱**（第 1 条② + 近通栏）：首屏第一眼问题；眉题修复是纯 CSS 小改，近通栏需视觉对比。眉题修复直接修改；通栏幅度先做方案对比。
3. **图片加载空白块**（第 3 条③）：今日评审亲见的缺陷，骨架屏缺失的直接后果；纯 CSS 占位即可解决。直接修改。
4. **卡片收藏按钮噪音 + 信息堆叠**（第 4 条）：六张卡片重复六次全宽按钮是全站最显眼的噪音；改动集中在 `destCard` 一个组件。直接修改。
5. **强调色孤立 + 详情页重复与粉红天气条**（第 2 条① + 第 5 条③）：品牌识别度与信息节奏问题；强调色方案二选一需先做对比，重复删除与天气条改色可直接修改。

## 五、直接修改 vs 先做视觉方案对比

**直接修改（问题明确、方案唯一、改动集中）**：画廊缩略图/箭头与灯箱箭头；图片加载占位；卡片收藏按钮降级与标签上限；详情页地区重复删除；天气条系统配色；省份入口换行/收起；规划表单网格重排与日卡片图文化；草案来源说明；死 Token 清理；收藏按压过渡。

**先做视觉方案对比（涉及品牌判断、多方案可选，须先出静态 mockup 与截图、由项目负责人选定后再写代码）**：① 首页主视觉幅度（内嵌圆角 vs 近通栏 vs 全通栏）；② 眉题可读性方案（顶部暗角/药丸底 vs 移至白底区）；③ 强调色方案（陶土体系化 vs 废除陶土全深绿）；④ 品牌识别装置（印章式小标 vs 期号式眉题，二选一）；⑤ 画廊裁切方案（补 focus 评审 vs 改 8/5 全高展示）；⑥ 页内导航位置（事实条后 vs 吸顶复现）；⑦ 首页精选与发现页卡片差异幅度。

**对比方法**：用静态 HTML mockup（不碰产品代码）在 workspace 临时目录出 2–3 套截图，390/1440 两档对照，附对比度实测与改动范围说明，由项目负责人选定；未选定的方案不进代码。

## 六、如何确保第二轮不是继续堆功能

1. **问题驱动清单**：本方案每一项都对应今日评审或代码审计中写明的具体问题；无对应问题的改动不得立项。新增功能（地图、预订、价格、日历支付、新页面）一律不在第二轮范围内。
2. **先图后码**：对比类项目先出 mockup 截图、选定后再写代码；直接修改类项目先出改前截图、改后截图对照。没有前后截图的改动不算完成。
3. **预算硬约束**：零新增 JS 依赖、零网络字体、零第三方图片请求、零 WebGL/3D/Lottie 运行时；图片只用已有封面图；动效只允许第 6 条列出的三类。
4. **回归与诚实验收**：沿用上一轮测试体系（单测、数据校验、双浏览器冒烟、UI 专项、溢出矩阵），并补三项上一轮缺失的验收：390px 真实视口截图、懒加载占位截图、对比度复算；K80 真机抽查仍列为待办，不得用桌面模拟代替；未执行项在报告中明示。
5. **分批交付、门禁不变**：方案对比 → 直接修改批 → 选定方案实施批 → 全回归 → 审查报告 → 授权后才推送；推送仍走 Git Data API 重放（非强推）、线上版本三处一致核查、线上真实浏览器验收，任一门禁不过即停。
