## 4. 详情页单图问题的根本原因（逐层追查）

1. **数据层——无问题**：正式集 `data/destinations/first-batch.json` 30 条记录，每条 3–5 张图，共 93 张；黄山记录 3 张。索引 `data/destinations-index.json` 不含 `images` 数组是**设计如此**（索引只含 `coverFull`/`coverThumb`/`shard`），详情页按分片加载完整记录，不影响多图；索引缺失 images 字段不是单图原因。
2. **渲染层——根本原因在此**：线上 1.0 的 `pages-detail.js` 只渲染 `imgs[0]`（单张主图 + 来源说明），无画廊结构；本地 2.0 的同一文件渲染 `<div class="gallery"><div class="gallery-track">` 并循环全部 `imgs` 为 `<figure class="slide">`。不存在“画廊组件未被调用”或“样式隐藏其他图片”的情况——线上代码里根本没有画廊组件。
3. **资源层——无问题**：线上详情唯一图片 `huangshan-1.webp` 最终可显示；本地 3 张图文件均存在（93 张正式图文件无缺失，上一轮已核验）。图片路径、格式、登记与引用一致。
4. **浏览器层——已实测**：线上黄山详情 article 内 1 个 `<img>`，无 gallery-track；本地同一页面 3 个 slide、1 个 gallery-track。结论：**单图是线上旧代码的行为，不是数据缺失、不是渲染 bug、不是加载失败。**

## 5. 首页和列表页图片问题的根本原因

- **首页主视觉缺失**：远程 main 的 1.0 首页代码中没有 hero（`pages-home.js` 无 hero 相关代码，`main.css` 无 `.hero` 规则）；首屏大图 + 搜索是 2.0 第一轮（`13fe86c`）加入的，从未部署。线上首页“文字主视觉 + 下方卡片图”正是 1.0 的预期表现。
- **列表卡片图片**：1.0 已有卡片图（`coverThumb`），线上卡片图正常显示；缺失的是 2.0 的卡片比较信息行（天数/季节）、悬停效果与筛选状态条——均为未部署项，不是图片本身的问题。
- **图片与目的地匹配、裁切、比例、占位**：本地均已验证（画廊专项、裁切验收、焦点修复）；线上 1.0 的单图与卡片图同样来自同一批已登记图片，不存在错配。移动端布局问题未在线上发现（线上页面在真实浏览器中完整渲染）。
